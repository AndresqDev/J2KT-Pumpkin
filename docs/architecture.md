# Architecture

J2KT is a source-to-source translator. It does not execute Java and does not provide a JVM for the resulting plugin.

## Pipeline

```text
Java source
  -> JavaParser AST + symbol solver
  -> KotlinEmitter
  -> Kotlin source
  -> Kotlin/Wasm compiler
  -> Pumpkin Gradle plugin component assembly
  -> .wasm plugin
```

The translator uses `libs/pumpkin-stub.jar` as the Java type contract. The generated Kotlin is compiled against the real Pumpkin Kotlin/Wasm API, not against the stub.

## Modules

| Path | Responsibility |
|---|---|
| `src/main/java/dev/j2kt` | Parser, type oracle, emitter, diagnostics, CLI, and library entry points |
| `pumpkin-compat` | Kotlin helpers for events, commands, tasks, IPC, AI goals, GUI, inventory, forms, recipes, datapacks, scoreboard, display entities, and player operations |
| `templates/intellij-plugin` | Standalone IntelliJ project using the translator and bundled artifacts |
| `examples/wasm` | Java sources used by the Wasm integration suite |
| `wasm-tests` | Kotlin/Wasm projects that compile generated sources and validate components |
| `libs/pumpkin-stub.jar` | Test classpath stub |

The stub source and release are maintained separately:

```text
https://github.com/AndresqDev/Pumpkin-Stub
```

## Type mapping

The translator maps Java stub types to the generated Pumpkin types. Common mappings include:

```text
plugin.PumpkinPlugin                 -> plugin.PumpkinPlugin
pumpkin.Player                       -> pumpkin.Player.Player
pumpkin.Server                       -> pumpkin.Server.Server
pumpkin.TextComponent                -> pumpkin.Text.TextComponent
pumpkin.Event.EventType              -> pumpkin.Event.EventType
pumpkin.Command                      -> pumpkin.Command.Command
```

`TypeMapper` owns the mapping table. `KotlinEmitter` handles syntax and expression-level rewrites.

## Compatibility layer

`pumpkin-compat` provides helpers that are not generated by `pumpkin-api-kt`:

- `events.listen` registration and dispatch.
- `commands.register` with handler ID attachment.
- Repeating tasks through `compatTasks.everyTicks`.
- IPC callbacks.
- AI goal dispatch.
- Builders and convenience methods for GUI, inventory, forms, dialogs, recipes, datapacks, scoreboard, display, and player operations.

The generated Kotlin source extends `PumpkinCompatPlugin` by default. Use `--no-compat` only when the target API already provides equivalent helpers.

## Resource ownership

The generated Kotlin/Wasm wrappers consume resource handles passed to methods. A resource must not be reused after it is passed to the API. Examples:

- `BossBar.addPlayer(player)` consumes the player handle.
- `BossBar.setTitle(text)` consumes the text handle.
- `BossBar.removeAll()` closes the bar without reusing a player handle.

See `COMPATIBILITY.md` for the current rules.

## Tests

The translator test suite covers golden Java-to-Kotlin cases. The Wasm suite covers compilation, linking, and component validation. Runtime testing against Pumpkin is separate; TPSBar Java is used as the live integration target.
